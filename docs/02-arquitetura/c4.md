# Diagramas C4

> [Índice](../README.md) › Arquitetura › C4
>
> **Responde a:** quais sistemas e containers existem? como a API se divide por dentro? onde moram regras, estatística e modelos? o que roda no hot path e o que roda no cold path? como o backtest roda sem HTTP e sem banco?

O [modelo C4](https://c4model.com) desenha o sistema em níveis de zoom: **contexto** (quem usa), **containers** (o que roda separado) e **componentes** (os módulos dentro de um container). Os diagramas são Mermaid C4 e renderizam no GitHub.

## 1. Contexto

```mermaid
C4Context
    title Contexto: motor antifraude Pix

    Person(risco, "Time de risco", "Calibra regras, treina modelos e lê as análises")
    System_Ext(pagamento, "Sistema de pagamento Pix", "Banco cliente ou a banca do hackathon: manda o Pix antes de liquidar")

    System(motor, "Motor antifraude Pix", "Recebe o Pix, decide approved / two_factor_required / rejected e grava a análise com o motivo")

    System_Ext(med, "MED e contestações (futuro)", "Desfecho real da fraude: viraria rótulo")
    System_Ext(twofa, "Fluxo de 2FA (futuro)", "Confirmação do cliente: rótulo fraco e imediato")

    Rel(pagamento, motor, "POST /pix/transaction, GET /pix/transaction/{id}", "HTTPS + INTERNAL-TOKEN")
    Rel(risco, motor, "Simula, calibra, treina", "make simulate / calibrate / train-models")
    Rel(med, motor, "Rótulos atrasados (fora do escopo)")
    Rel(twofa, motor, "Resultado do 2FA (fora do escopo)")
```

O motor não chama nada de fora no caminho da decisão ([ADR 0002](decisoes/0002-monolito-sincrono-sem-dependencia-externa.md)). MED e 2FA aparecem só como a origem futura dos rótulos ([ADR 0017](decisoes/0017-ml-fora-do-prazo-e-do-hot-path.md)).

## 2. Containers

```mermaid
C4Container
    title Containers: o que roda separado

    System_Ext(pagamento, "Sistema de pagamento Pix", "Cliente da API")
    Person(risco, "Time de risco")

    System_Boundary(motor, "Motor antifraude Pix (docker compose)") {
        Container(api, "api (hot path)", "Python 3.11, FastAPI, SQLAlchemy 2", "Valida o contrato, carrega o histórico, roda 18 regras + 5 modelos em shadow, decide e grava")
        Container(worker, "worker (cold path)", "Python 3.11 + numpy", "A cada 30 s: reputação por grafo em SQL, GraphSAGE e HMM; grava scores")
        ContainerDb(db, "db", "PostgreSQL 16", "pix_transaction, pix_analysis, pix_analysis_reason, account_risk_score, payer_sequence_score (append-only)")
    }

    Container(sim, "Simulador", "scripts/simulate.py, replay.py", "Gera Pix legítimos e fraudes rotuladas; manda pela API em ordem cronológica")
    Container(bt, "Backtest em lote", "scripts/backtest.py", "O mesmo motor sobre um arquivo de eventos, sem HTTP e sem banco (~8 mil Pix/s)")
    Container(tests, "Suíte de testes + CI", "pytest, GitHub Actions", "Black box por HTTP; paridade API × backtest; trava de calibração")

    Rel(pagamento, api, "POST/GET /pix/transaction", "HTTP/JSON")
    Rel(api, db, "Agregados por janela, scores recentes, INSERT", "SQL")
    Rel(worker, db, "Lê o grafo e as sequências, grava scores", "SQL")
    Rel(risco, sim, "make simulate")
    Rel(risco, bt, "make backtest / calibrate / datasets")
    Rel(sim, api, "Milhares de POST, rótulo guardado no script", "HTTP/JSON")
    Rel(tests, api, "POST/GET", "HTTP/JSON")
    Rel(tests, worker, "1 ciclo por teste (docker compose run --once)")
```

`api` e `worker` usam o mesmo código (`src/`), em targets diferentes do Dockerfile: só o worker tem numpy ([ADR 0026](decisoes/0026-graphsage-e-hmm-no-worker.md)). Simulador, backtest e testes rodam na máquina de quem desenvolve e no CI.

## 3. Componentes da API

```mermaid
C4Component
    title Componentes da api: camadas do Base Service + motor

    Container_Ext(cliente, "Cliente HTTP", "Sistema de pagamento, simulador ou pytest")
    ContainerDb_Ext(db, "db", "PostgreSQL 16")

    Container_Boundary(api, "api") {
        Component(mw, "Middlewares", "src/middlewares/", "Request id, log, INTERNAL-TOKEN (403), sessão de banco")
        Component(schema, "SchemaHandler", "src/utils/schema_handler.py + src/schemas/", "JSON Schema fechado do payload (400)")
        Component(resource, "PixTransactionResource", "src/resources/", "HTTP de entrada e saída; 201 ou 200")
        Component(controller, "PixTransactionController", "src/controllers/", "Idempotência, snapshot, chama o engine, grava, commit")
        Component(repo, "PixTransactionRepository", "src/repositories/", "Implementa HistoryPort em SQL: agregados por janela e scores do cold path")
        Component(engine, "Motor", "src/rules/engine.py", "build_context, evaluate, metadata_from")
        Component(dto, "PixAnalysisDTO", "src/dtos/", "{key, status, metadata}")
        Component(errors, "Erros QIT", "src/errors/", "404 QIT002001, 409 QIT002002")
    }

    Rel(cliente, mw, "HTTP")
    Rel(mw, schema, "")
    Rel(schema, resource, "payload válido")
    Rel(resource, controller, "analyze / get_by_pix_id")
    Rel(controller, engine, "snapshot + history")
    Rel(engine, repo, "agregados via HistoryPort")
    Rel(repo, db, "SQL")
    Rel(controller, dto, "monta a resposta")
    Rel(controller, errors, "levanta recusa")
```

O controller não tem regra nem SQL de agregado. O motor só conhece o `HistoryPort`, e por isso o mesmo código roda no backtest ([ADR 0023](decisoes/0023-motor-extraido-e-history-port.md)).

## 4. Componentes do motor

```mermaid
C4Component
    title Componentes do motor: regras, estatística, modelos e shadow

    Component_Ext(controller, "PixTransactionController / backtest.py", "chamadores", "Passam snapshot e um HistoryPort")

    Container_Boundary(rules, "src/rules/") {
        Component(engine, "engine.py", "Python", "Monta o RuleContext, roda todas as regras, separa shadow, decide por severidade")
        Component(port, "HistoryPort", "history_port.py", "Contrato dos agregados (SQL na api, memória no backtest)")
        Component(features, "features.py", "Python", "Vetor único de 33 features, sem dado identificável")
        Component(det, "Regras determinísticas", "limit_*, velocity_*, amount_*, profile_new_*, counterparty_*", "Limites, contagens e idades")
        Component(stat, "Regras estatísticas", "profile_amount_robust_z, velocity_poisson_gamma, profile_geo_velocity", "Perfil do próprio pagador (ADR 0016)")
        Component(typo, "Tipologias", "typology_*", "Combinações que descrevem um golpe: rejected (ADR 0018)")
        Component(graph, "COUNTERPARTY_GRAPH_RISK", "counterparty_graph_risk_rule.py", "Lê o score de grafo do worker e decide (ADR 0025)")
        Component(models, "Modelos em shadow", "models/ + model/*.json", "LogReg+Platt, LightGBM, Isolation Forest em Python puro; GraphSAGE e HMM lidos da tabela")
        Component(stats, "Estatística pura", "signals.py, src/utils/statistics.py", "z robusto, cauda binomial negativa, haversine")
    }

    Rel(controller, engine, "")
    Rel(engine, port, "agregados")
    Rel(engine, det, "evaluate")
    Rel(engine, stat, "evaluate")
    Rel(engine, typo, "evaluate")
    Rel(engine, graph, "evaluate")
    Rel(engine, models, "evaluate (shadow: nunca decide)")
    Rel(engine, features, "monta o vetor")
    Rel(models, features, "lê o vetor")
    Rel(stat, stats, "usa")
    Rel(typo, stats, "usa")
```

Regras que decidem vão para `status` e `reasons`; regras shadow, só para `metadata.shadow` ([ADR 0022](decisoes/0022-shadow-mode.md)). Nada aqui importa banco, ambiente ou relógio.

## 5. Componentes do worker (cold path)

```mermaid
C4Component
    title Componentes do worker: scores pré-calculados

    ContainerDb_Ext(db, "db", "PostgreSQL 16")
    Container_Ext(api, "api", "hot path", "Lê o score mais recente com até 120 min")

    Container_Boundary(worker, "worker (python -m worker)") {
        Component(loop, "Laço", "src/worker/__main__.py", "A cada 30 s, no relógio dos dados; --once para testes; um job falhando não para os outros")
        Component(graphjob, "GraphRiskJob", "graph_risk_job.py", "Funil, dispersão, 2 saltos e idade em SQL; score logístico com pesos fixos")
        Component(sage, "GraphSageJob", "graphsage_job.py + graphsage.py", "Subgrafo da janela, forward de 2 camadas em numpy")
        Component(seq, "SequenceJob", "sequence_job.py + hmm.py", "Últimos Pix do pagador, log-verossimilhança no HMM, CDF de anomalia")
    }

    Rel(loop, graphjob, "")
    Rel(loop, sage, "")
    Rel(loop, seq, "")
    Rel(graphjob, db, "account_risk_score (graph_sql)")
    Rel(sage, db, "account_risk_score (graphsage)")
    Rel(seq, db, "payer_sequence_score (hmm)")
    Rel(api, db, "lê scores")
```

Ciclo completo no cenário padrão: 0,31 s ([ADR 0025](decisoes/0025-cold-path-worker.md), [ADR 0026](decisoes/0026-graphsage-e-hmm-no-worker.md)).

## 6. Backtest em lote e treino (offline)

```mermaid
C4Container
    title Offline: PixSim, backtest, paridade, calibração, treino e retroalimentação

    Person(risco, "Time de risco")
    ContainerDb_Ext(events, "events.jsonl", "Arquivo", "Pix em ordem cronológica + rótulo + atraso de reporte ao MED")
    System_Ext(pixsim, "PixSim (terceiro)", "Simulador de Pix calibrado com dados do BCB; venv isolado em scripts/out/pixsim/")

    System_Boundary(off, "scripts/") {
        Container(bt, "backtest.py", "Python", "Motor real sobre InMemoryHistory; ~8 mil Pix/s")
        Container(mem, "InMemoryHistory", "Python", "Implementa HistoryPort com índices em memória")
        Container(parity, "parity.py", "Python", "API × backtest Pix a Pix: status, regras e as 33 features")
        Container(cal, "calibrate.py", "Python", "Grid de parâmetros, função objetivo, trava de regressão")
        Container(train, "train_models / train_graphsage / train_hmm", "numpy, scikit-learn, lightgbm (só dev)", "Treina e exporta JSON")
        Container(adapter, "pixsim_adapter.py", "Python", "Converte o mundo do PixSim para o contrato do enunciado")
        Container(feedback, "feedback.py", "Python", "Desfechos do MED no tempo, fraude confirmada, retreino semanal com champion/challenger")
    }

    Container_Ext(api, "api", "hot path")
    Container_Ext(core, "src/rules/", "motor compartilhado, sem alteração")

    Rel(risco, cal, "make calibrate / calibrate-check")
    Rel(bt, events, "lê")
    Rel(bt, core, "engine.evaluate")
    Rel(bt, mem, "HistoryPort")
    Rel(parity, bt, "compara")
    Rel(parity, api, "compara")
    Rel(cal, bt, "uma rodada por combinação")
    Rel(train, bt, "features + rótulo")
    Rel(train, core, "grava model/*.json")
    Rel(pixsim, adapter, "transações, contas, atrasos de reporte")
    Rel(adapter, events, "gera")
    Rel(feedback, bt, "replay com desfechos")
```

O backtest é a proposta do primeiro C4, agora implementada: as 5.062 Pix do cenário padrão levam 0,6 s, contra 206 s pela API, com zero divergências na paridade. As métricas de referência vêm do PixSim ([ADR 0029](decisoes/0029-pixsim-como-referencia.md)); a retroalimentação pelo MED existe só aqui, no backtest ([ADR 0032](decisoes/0032-retroalimentacao-pelo-med-no-backtest.md)).
